# 04 — Reserve 10–12 weeks of capacity and record the Phase 0 Lite refusal

**What to build:** The fourth start precondition, and the one that protects the design from being
quietly compressed. This ticket ends with a reserved 10–12 week block recorded against named people,
weeks 11–12 explicitly held as contingency rather than planned work, and a written refusal of a
reduced-rigour "Phase 0 Lite" run recorded in the register so that a later request for one is a
recorded exception rather than a reasonable-sounding shortcut.

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] A 10-week target and a 12-week planned maximum are reserved against the named Primary Builder
      and Independent Validator, with weeks 11–12 marked as contingency for decoder gaps, incomplete
      data, golden-set discrepancies, trace problems, or a required validation re-run.
- [ ] The reservation is recorded against calendar dates, not as an intention.
- [ ] The register records `phase_0_lite: REFUSED` with the reason: no confirmed external deadline is
      on record.
- [ ] The register records the standing rule that if the full run is not resourceable the correct
      action is to **pause the project**, not to run a weak test whose result would later be cited as
      evidence.
- [ ] It is recorded that a reduced-rigour run is most likely to produce a false positive
      specifically on uncopyable trades and pricing errors — the exact failures the gates exist to
      catch — so the refusal is justified rather than stylistic.
- [ ] Any request to observe a raw number early is recorded as contaminating a pre-registered design
      and is refused by the same rule.
- [ ] The register entry is machine-readable and exposes `capacity_reserved: YES | NO`.
